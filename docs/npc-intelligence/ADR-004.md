# ADR-004 — NPC Intelligence Layer: model-agnostic acting on a deterministic engine

Status: **accepted (2026-11-10)** · supersedes nothing; extends ADR-001/002 in `docs/v10-ai-architecture.md`.

## Context
v10 shipped a deterministic intent engine and an optional `/api/npc` classifier hard-wired to one
OpenAI-compatible call. The 2026-11 brief asks for natural, context-aware, character-consistent interviews with
interchangeable models, without letting any model decide facts, disclosure, evidence or outcomes.

Audit findings that shaped the decision (repository state `97be5fe`):
- Every question path already ends in `interview-engine.submitUtterance()` → `case-engine.ask()`; reused as-is.
- `/api/npc` sent **every** question of a case to the model, including questions whose disclosure condition was
  unmet (answers were never sent). Fixed: menus now hold disclosure-ready questions only.
- There was no provider abstraction, health/circuit state, structured error category, cancellation of stale turns,
  per-session rate limit, acting layer, conversation memory, follow-up handling or multi-question handling.
- `dialogue-guard.publicRecord` reads `name, displayNameKo, nat, purpose, stay, arrival, return, basis,
  basisDetail, visa, docs` — all rendered on the desk at case start (`ui/system-panel.js`,
  `ui/passenger-panel.js`, `ui/document-workbench.js`); verified in `tests/e2e/npc-intelligence.spec.js`.
  No hidden field leaks through the guard.
- The v10 "held-out" intent fixtures score 100 % because they were folded into tuning; a new held-out corpus was
  written and committed before any engine change (`3d2b937`).

## Decision
**AI is the actor; the deterministic engine is the source of truth.** One contract, two tasks, closed outputs:

| Task | Model output | Accepted only if | What it can change |
|---|---|---|---|
| `classify` | `{questionId: id \| null}` | id ∈ open menu (server) **and** ∈ open questions (client) | nothing until the examiner confirms; then the same path as a click |
| `act` | `{reaction, leadId, gesture, pause}` | every value ∈ closed enum; `leadId` ∈ this persona's approved leads for this turn kind | delivery of the line just recorded (mood, approved lead-in) — never its words, evidence, cost or score |

Layers (all pure except the transport and UI):
```
src/data/npc-profiles.js     immutable character profiles (style, temperament, pace, formality, habits, leads)
src/data/npc-leads.js        approved, content-free lead-ins (ids → words); guard-checked
src/js/engines/npc-contract.js   enums, schemas, validators, error categories, limits  (browser + server)
src/js/engines/npc-context.js    disclosure-aware context builder + outbound audit      (browser + server)
src/js/engines/npc-memory.js     per-case, id-only, bounded memory (reset with the interview record)
src/js/engines/npc-acting.js     deterministic acting; validation/merge of a model proposal
src/js/engines/intent-engine.js  + follow-up references (memory) + two-questions-at-once
src/js/engines/interview-engine.js  + memory, acting per turn, refineTurnActing(seq, proposal)
src/js/engines/npc-equivalence.js   Stage 3 research gate (not wired)
src/js/services/npc-client.js    transport: health, deadlines, cancellation, stats, session id
src/js/ui/live-interview.js      orchestration: deterministic first → optional classify → confirm; acting in the
                                 reaction-delay window; quiet degraded note
api/npc.js                       boundary: strict request schema, rate limits, context build, audit, provider call
api/_npc/config.js · providers.js · prompts.js   provider registry from server env only
```

Providers: `deterministic` (rules; always on in the browser; also a server adapter for the harness),
`openai-compatible` with presets `vllm`, `llamacpp`, `ollama` (differ in structured-output default and the
thinking switch). Ollama/vLLM/llama.cpp local servers and hosted OpenAI-compatible providers are configuration,
not code. Swapping a model = changing `INAD_LLM_MODEL` (and possibly `INAD_NPC_PROVIDER`).

Fallback policy: every non-success (not configured, circuit open, timeout, cancel, HTTP, 429, non-JSON, malformed,
invalid value, schema unsupported, audit block) yields "no model result" and the turn continues on the
deterministic result already computed. Acting requests are bounded by the passenger's reaction delay, so a model
never slows a line; reduced motion skips model acting entirely.

### Staging
- **Stage 1 (shipped):** canonical answers + model classification + validated acting choices.
- **Stage 2 (shipped, deterministic):** follow-up references resolved against id-only memory (always confirmed),
  repeat awareness with consistent canonical re-statements and temperament-consistent acting, withheld callbacks
  ("아까 말씀드린 대로,") from the approved lead set. Every factual claim is a canonical answer or a public-record line.
- **Stage 3 (research only, not wired):** `npc-equivalence.realizationCheck` shows why token overlap is
  insufficient (a negation flip passes `checkLine`, fails the gate). No build generates or shows paraphrases.
  Enabling it would need a separate decision, a labelled paraphrase corpus, live-model measurements and human review.

## Consequences
- Zero model-authored facts by construction; identical evidence and legal outcome across list/text/voice/model paths
  (`tests/unit/npc-layer.test.js`).
- A question outside the open menu cannot be chosen by a model; gated questions are still answerable
  deterministically (withheld line until their condition is met).
- One more server round trip per answered line when `act` is enabled (cost on the operator's inference endpoint).
  `INAD_NPC_TASKS=classify` disables it.
- Live model quality is **unmeasured** (no reachable endpoint in this environment) — see MODEL_EVALUATION.md.

## Rejected
- Free-form model dialogue / paraphrase in production (wording drift becomes evidence drift; token guards miss
  meaning changes — demonstrated).
- Browser-chosen provider URL or model (SSRF, key exposure, cost abuse).
- Sending `performed`/answers to the server so it can rebuild disclosure (the browser could lie; menus are narrowed
  to the server's own open set ∩ the browser's list instead, and no answer text is ever needed).
- Forcing v11 ATLAS into this pipeline (its intent layer has its own data and rules; see README §ATLAS).

# 07 — Validation, stop gates and roadmap

**PROPOSED. 사람 플레이테스트는 아직 한 명도 실시하지 않았다.** 아래 목표는 산업 benchmark나 통계적으로 검증된 성공공식이 아니라 적은 비용으로 잘못된 방향을 중단하기 위한 운영 기준이다.

## 모집과 연구 구성

목표10명, 허용8–12명. 기본 구성: 법률 배경 없는 추리/시뮬레이션 비숙련4명, 장르 숙련4명, 나머지2명은 혼합. Papers, Please를 실제 플레이한 사람 최소4명 확보. 법률 직업인만 모집하거나 기존 개발 지인만 모집하지 않는다. 스마트폰 주 사용자를 최소4명 포함하고 키보드만 사용하는 세션도 최소2회 배정한다. 스크린리더 검증은 이 소표본에 포함됐다고 간주하지 않고 별도 접근성 점검으로 둔다.

참여자의 이민 상태·국적·법적 경험은 수집할 필요 없다. 게임 이해력 테스트임을 설명하고 언제든 중단할 수 있다. 녹화/발화 기록은 별도 동의, 기본은 ID별 관찰표와 선택 로그. 원문 대사 입력은 수집하지 않는다. 외부 전송/상업적 분석 서비스 가입은 필요 없다.

### 세션 약40–50분

1.5분: 장르 경험과 입력 장치 확인. 핵심 mechanic을 미리 설명하지 않는다.
2.15분: RB-R01 blind play. 첫5분에는 개발자가 답을 알려주지 않는다. 요청한 도움과 제공한 도움을 분리 기록.15분에 끝나지 않아도 강제 실패처리하지 않고 어디서 막혔는지 기록한다.
3.3분: debrief 정답 공개 **전** ‘왜 이 근거를 유지/철회했는가’, decision confidence0–100, 다음 담당자가 무엇을 해도 되는지 질문.
4.5분: debrief를 본 후 본인의 판단에서 무엇이 바뀌었는지 설명.
5.5분: 다른 사건 체험 선택/예약 등 실제 행동 기회. 둘째 case가 아직 없으면 ‘지금 플레이’ 버튼으로 속이지 않고 향후 체험 신청임을 표시.
6.7–15분: 재미/agency/다시 하기/비교작 질문. 비교작 이름은 자유 응답을 받은 뒤 묻는다.

가능하면 기존 INAD 대표1case와 짧은 비교도 별도 세션에서 한다. 같은 사람에게 두 버전을 주면 순서를 반반 교차하고 학습효과를 기록한다. 기존 제품의 버그와 새 제품의 미완성 미술을 품질 차이로 혼동하지 않는다. 이 비교는 optional이며 핵심 슬라이스 연구와 시간을 혼합하지 않는다.

## 사전 등록할 gate

주요 기준과 분모를 연구 전에 고정한다. 이탈도 분모에서 지우지 않는다. 기술적 설치 불가와 자발 중단은 별도 표시하고 두 분모를 모두 보고한다.

| gate | 목표 | 실패 시 결정 |
|---|---|---|
| G1 이해 | 전체≥70%가 도움 없이 주행동 수행 및 철회/사실삭제 차이 설명 | 인터페이스/용어 수정1회, 다시 같은 방식으로 검증 |
| G2 첫 행동 | 중앙값≤120초,75%가180초 내. 목표치일 뿐 | 첫 화면과 자료 수 축소, 힌트로 정답 직접 노출 금지 |
| G3 완료 |≥80%가20분 내 개발자 해답 제공 없이 유효 인계 | softlock이면 engineering, 해석불능이면 mechanic redesign |
| G4 signature |≥70%가 출처 계보와 하위 주장 지원의 변화를 정확히 설명 | 새 방향의 핵심 실패. 화면 polish로 통과 처리 금지 |
| G5 재플레이 |≥60%가 구체적으로 다음 사건을 원함; 실제 행동은 별도 실수 보고 | 실제 선택이 진술보다 현저히 약하면 콘텐츠 추가 보류 |
| G6 PP 차이 | PP 경험자 중≥70%,최소4명 분모, 주제·그래픽 외 차이1개 설명 | 비교 대상 인지 부족으로 제외하지 말고 direction 재평가 |
| G7 기술 | critical path softlock/상태손상0,모바일/키보드 필수 흐름 완료 | 사람 연구 확대 전에 수정, 동일 경로 회귀 검증 |
| G8 공정성 | 진술/기록 범위와 성과를 설명 가능. 중대한 보호속성 proxy0 | 내용/규칙 차단, 법률/윤리 경계 다시 검토 |

70% 기준의 최소 인원: n8이면6명,n10이면7명,n12이면9명.60%는 각각5/6/8명. PP경험자4명이면3명이 구체적 차이를 설명해야 한다. n4에서 한 사람 차이는25%p이므로 이를 확정적인 시장 증거로 해석할 수 없다. gate 통과는 더 큰 투자 검토 권한을 줄 뿐 성공 확률을 추정하지 않는다.

agency 점수 중앙값5/7은 보조 지표로 본다. 평균 만족도 하나로 핵심 이해 실패를 상쇄하지 않는다. ‘다음 사건 선택’은 둘째 사건이 실제 제공됐는지, 예약 의향인지 구분해 보고한다.

## 중단·축소·재설계

- **즉시 기술 중단:** 미획득 사실 노출, 저장 손상, 불가능한 handoff state. 새로운 기능을 추가하지 않고 경계를 먼저 수정.
- **범위 축소:** desktop에서는 이해하지만 mobile 왕복이 큰 경우 graph를 목록형으로 낮추고 자료 수를 줄임. 앱을 새로 만들지 않음.
- **mechanic 재설계:** 참가자가 올바른 노드를 찾는 클릭 퍼즐로만 인식하거나 어떤 확인을 해도 같은 결과라고 느끼면 다른 선택/결과 관계를 설계.
- **architecture 재검토:** 새2case를 넣을 때마다 핵심 reducer를 갈아엎거나 hidden canon을 UI에 흘려야 하면 도메인 모델이 잘못됨. framework 전환이 첫 해법 아님.
- **다음 prototype:** G1/G7은 통과하나 G4/G5가 경계면인 경우 한 번만 가설을 바꾸어 재시험. 같은 참가자 학습효과를 피하려고 새로운 표본 우선.
- **ARCHIVE:** 총2회 외부검증 후 G4 또는 G5 지속 실패, 또는 3번째 case 작성+검증이16h를 반복 초과하고 줄일 방법이 없을 때. 비용이 이미 들었다는 이유로 추가하지 않음.
- **CONTINUE 재검토:** 기존 INAD 비교군에서 더 강한 이해·재플레이·고유 가치가 반복 관찰되면 E를 포기할 수 있음.

## 자원·금액·모델 사용

현 슬라이스의 runtime inference 호출은0. 정적 hosting의 기존 한도/정책은 따로 확인해야 하므로 ‘모든 운영비 무료’라고 하지 않는다. 기존 구독의 coding usage는 한도와 약관에 따라 달라진다. 새 구독/추론 endpoint를 이 단계에서 생성하지 않는다.

향후 분류 실험 예산 산식(가정):10명×2case×12turn=240회. 매회 input1,500tokens/output80tokens이면 총input360,000/output19,200. 입력100만 token당 단가 `p_in`, 출력 단가 `p_out`일 때 `0.36*p_in + 0.0192*p_out`. retry20%라면 호출비에1.2를 곱하고 hosting/logging 비용은 별도다. 이 값은 현재 모델 단가 인용이 아니다. 실행 직전 실제 provider와 모델ID·가격·timeout·지역을 확인한다. open-weight도 GPU/idle 시간·운영 노동 비용을 계산해야 한다.

사람 연구 보상 예산 예:10명×20,000원=200,000원. 이는 지출 제안이며 이미 지급/예약한 것이 아니다. 금액은 모집 조건에 맞춰 소유자가 결정한다. 가장 큰 비용은 추론료보다1인 개발시간과 반복 가능한 사건 작성이다.

**모델 배분:** 전략 저자는 현재 Work 세션; 독립 reviewer는 Claude Code의 Opus5.5가 실제 선택 가능할 때1종합 검토. 실행 불가면 대체 모델을 몰래 썼다고 기록하지 않고 사용자 환경에서 가능한 모델을 확인한다. 검토 사용량 계획은1세션, 누적입출력40k–100k tokens 범위 내 필요한 만큼, 실제 quota/문맥 한도 우선. 이후 승인된 domain spike는1구현+1반례검토, 누적40k–80k 계획 상한. 토큰 소진이 목표가 아니고 런타임 게임은 모델과 독립이다.

# 03 — Five game directions

전부 **PROPOSED**다. 기존 소스 재사용 가능성은 감사에 근거하지만 재미 점수는 저자의 설계 판단이다. 인물/법률/AI를 바꾸는 리스킨 다섯 개가 아니라 플레이어가 무엇을 결정하는지 다르게 구성했다.

## A — 절차 조사: 무엇을 더 알아야 하는가

| 항목 | 설계 |
|---|---|
| 1 정체성 / 2 fantasy | 제한된 사실로 다음 확인을 골라 정당한 절차를 완성하는 조사게임 / 성급한 결론을 피하는 조사자 |
| 3 장르 / 4 loop | 대화형 procedural puzzle / 진술 수집→가설 두 개→구별할 조회 선택→절차 결정→근거 설명 |
| 5 보조 / 6 signature | 통역·진술 시간표 / **가설을 구별하는 질문 선택**: 둘 다 설명하는 질문은 정보 이득이 작음 |
| 7 불확실성 / 8 결정 | 누락·기억 착오·거짓이 공존 / 질문의 판별력과 소명 기회 사이의 선택, 독해시간은 비용 아님 |
| 9 서사 / 10 완결 encounter | 독립 사건 anthology. ‘초대 주체가 바뀐 방문’: 취업/무상 행사 가설→초대장 요청 대신 일정 확인→유급 업무 여부 unresolved→담당 절차로 이유와 함께 인계 |
| 11 결과 / 12 실패·회복 | 조사한 정보가 설명 가능한 결정 범위를 제한 / 잘못된 단정은 반론 받고 재조사, 끝까지 모르면 정당한 미해결 인계 |
| 13 난도 / 14 재플레이 | 처음2가설·3질문→시점/출처 혼합 / authored 분기·대안 조사 경로, 무작위 범인 교체 금지 |
| 15 재사용 / 16 새 기술 | interview/대사/문서 UI 일부 / 가설별 예측·조건부 관측·provenance graph 필요 |
| 17 AI / 18 콘텐츠 | AI 불필요, 자유입력 분류 optional / 질문마다 두 가설에서의 의미와 반론을 작성해 중간~높은 비용 |
| 19 인접작 / 20 약점 | Ace Attorney·The Operator, PP 심층 조사 확장 / 모든 확인을 누르면 끝나는 checklist로 퇴행하기 쉬움 |
| 21 복잡도 / 22 검증 | 중간, 1case domain+UI 대략40–65h 가정 / 세 질문 중 어떤 것이 구별에 유용한지 설명하고 순서가 실제로 달라지는지 관찰 |

## B — 사람 중심 국경 드라마: 누구에게 무엇을 약속하는가

| 항목 | 설계 |
|---|---|
| 1 정체성 / 2 fantasy | 같은 사람들을 다시 만나며 제한된 재량과 약속의 결과를 감당하는 이야기 / 제도 안에서 책임지는 사람 |
| 3 장르 / 4 loop | choice-driven drama / 상황 파악→허용된 지원·소명 방식 선택→약속 이행→후속 만남→결과 재해석 |
| 5 보조 / 6 signature | 시간표·인계 메모 / **약속 장부**: 무엇을 누구에게 언제까지 설명/전달하기로 했는지가 미래 선택지를 바꿈 |
| 7 불확실성 / 8 결정 | 타인의 기대·기관의 한계 / 권리를 거래하지 않고 설명/연결/우선 확인 등 적법한 재량 범위 안 선택 |
| 9 서사 / 10 완결 encounter |3인 반복 단편. ‘연락이 끊긴 보호자’: 통역으로 요청 확인→지원 창구 연결 또는 현재 정보로 인계→다음 회차에 누락된 설명이 드러남→약속 수정/이행 |
| 11 결과 / 12 실패·회복 | 관계와 정보 전달 결과, 호감=법적 유리함 금지 / 지킬 수 없는 약속은 공개 정정·인계로 회복; 거짓 위로는 서사 비용 |
| 13 난도 / 14 재플레이 | 한 약속→상충하지만 정당한 요구들 / 관점과 결과의 다른 조합, 도덕 정답 route 금지 |
| 15 재사용 / 16 새 기술 | personas·대화 log·debrief / 약속 상태·시간선·재등장 script, 지속 결과 저장 |
| 17 AI / 18 콘텐츠 | authored 필수, 모델 즉흥 약속 금지 / 분기 수·인물별 voice·후속 결과로 비용 높음 |
| 19 인접작 / 20 약점 | Beholder·PP 인간적 만남 / ‘친절 버튼’만 누르는 수동 소설, 감정 조작·권리의 보상화 위험 |
| 21 복잡도 / 22 검증 | 기술 중간·서사 높음, 1encounter+후속40–70h / 동등하게 정당한 선택 둘이 존재하고 플레이어가 비용을 회상하는지 |

## C — 운영 전략: 사람을 처리하지 않고 시스템을 배치한다

| 항목 | 설계 |
|---|---|
| 1 정체성 / 2 fantasy | 통역·전문심사·휴식 자원을 배치해 절차 품질을 유지하는 운영 시뮬레이션 / 병목을 이해하는 교대 책임자 |
| 3 장르 / 4 loop | constrained management / 수요 예측→역량 배치→시간 tick→병목/권리 대기 관찰→재배치 |
| 5 보조 / 6 signature | staff skill·교대·예비용량 / **서비스 약속을 보존하는 큐 재배치**: 단순 최대처리량 최적화와 분리 |
| 7 불확실성 / 8 결정 | 수요 변동·통역 소요·장애 / 예비 인력 유지와 지금의 지연 감소, 권리 서비스는 hard constraint |
| 9 서사 / 10 완결 encounter | 하루 단위 운영 일지. 항공 지연 뒤 통역 수요 집중→일반 창구 축소·통역 지원 확보→사람별 사건 내용과 무관하게 대기 개선→피로 남겨 다음 교대 인계 |
| 11 결과 / 12 실패·회복 | 평균뿐 아니라 최장 대기·누락·직원 회복 / 장애 때 신규 수용 제한·상급 지원 요청; 편법 생략 보상 금지 |
| 13 난도 / 14 재플레이 |2자원→호환 역량·예측오차 / 공개 seed와 demand pattern, 국적/외모 기반 위험생성 금지 |
| 15 재사용 / 16 새 기술 | operation/rng/queue 일부 / discrete event simulation·배치 편집·다목적 지표·밸런싱 |

| 21 복잡도 / 22 검증 | 높음, 작은2station 실험55–90h / 플레이어가 병목의 원인과 배치 tradeoff를 설명, 권리 위반 최적 전략이 없는지 |

## D — 연결 사건망: 무엇이 실제로 연결되는가

| 항목 | 설계 |
|---|---|
| 1 정체성 / 2 fantasy | 여러 기록의 관계를 검증하며 잘못 연결된 사람도 분리하는 장기 추리 / 네트워크의 원인과 우연을 구별하는 조사자 |
| 3 장르 / 4 loop | episodic network mystery / 개별 기록→관계 후보→독립 확인→연결/분리→다음 사건 재해석 |
| 5 보조 / 6 signature | 시간표·조직·자산 graph / **관계의 증명과 기각**: 같은 연락처만으로 공모를 확정할 수 없음 |
| 7 불확실성 / 8 결정 | 공통 서비스·복제 데이터·실제 협력 / 제한된 확인을 어떤 edge에 쓸지, 조사 범위를 어디서 멈출지 |

| 11 결과 / 12 실패·회복 | 연결이 후속 맥락을 바꾸고 분리도 성과 / 잘못된 edge는 반례에서 철회, 무고한 인물에 대한 추정 확산을 설명 |

## E — Wildcard: 두 번째 기록

| 항목 | 설계 |
|---|---|
| 1 정체성 / 2 fantasy | 이미 작성된 판단의 근거를 해체·복원하는 기록 검토 게임 / 자신보다 먼저 만들어진 오류를 책임 있게 고치는 사람 |
| 3 장르 / 4 loop | reasoning repair puzzle / 초안의 주장→원출처 추적→근거 철회→영향 확인→독립 근거 복구→범위를 정한 인계 |
| 5 보조 / 6 signature | 시간표·정정 응답 / **전제 철회**: 한 자료를 판단에서 제외하면 그 자료에만 의존한 결론이 지지를 잃음 |
| 7 불확실성 / 8 결정 | 같은 출처의 복사·다른 시점·증거 없는 확대 / 무엇을 유지/철회할지, 남은 슬롯으로 어떤 독립 확인을 할지 |
| 9 서사 / 10 완결 encounter | 독립 기록 모음. 숙소가 없다는 보고2개→둘 다 동일 cache에서 파생 확인→독립 corroboration 철회→전환 원장 확인→허위 진술 단정 수정, 목적 문제는 unresolved로 인계 |
| 11 결과 / 12 실패·회복 | 지원 가능한 주장/남은 공백이 이후 담당자에게 전달 / 모든 것을 부정해도 성공 아님; 철회는 undo, 제한을 드러내는 인계 허용 |
| 13 난도 / 14 재플레이 | 복사 출처→시점 범위→독립 증거 충돌 / 매 case 다른 추론 구조, 같은 트릭 연속 금지 |
| 15 재사용 / 16 새 기술 | 문서읽기·작성대사·빌드·저장검증 원칙 / 작고 결정적인 provenance/reducer·지원상태 계산 |
| 17 AI / 18 콘텐츠 | 불필요 /1graph·2가설·3확인 선택으로 좁힐 수 있음, 좋은 퍼즐 제작은 여전히 중간~높음 |
| 19 인접작 / 20 약점 | Orwell의 정보선택·논리 퍼즐 / ‘정답 노드 제거’가 되면 새 이름의 Lock. 내용이 교정 업무처럼 지루할 위험 |
| 21 복잡도 / 22 검증 | 중간, 도메인+UI40–65h / 철회의 결과를 예측하고, 사실 삭제와 지지 상실을 구별하며 다음 사건을 선택하는지 |

각 시간은 동일한 숙련자·기존 도구·작성형 1개 실험의 계획치다. 후보 간 확실한 생산성 차이를 측정한 값이 아니며 문서/외부 검증까지 포함한 전체 일정은 07에 별도로 있다.

## 가중 평가

사용자 제시 가중치 유지: 정체성25%, 재미/재플레이25%, 1인 제작20%, 재사용10%, 법·윤리·서사10%, UX10%. 점수1=근본 장애,3=유망하지만 큰 미검증,5=설계상 강한 우위. 0.5는 상대 판단 간격. 합계의 소수는 계산 결과이지 측정 정밀도가 아니다.

| 후보 | 정체성 | 재미 | 1인 | 재사용 | 견고성 | UX | 가중 합계/5 |
|---|---:|---:|---:|---:|---:|---:|---:|
| A |3.5|4|4|4.5|4|4|3.925|
| B |3.5|4|3|3|4|4|3.575|
| C |4|4|2.5|3|4|3|3.500|
| D |3.5|4.5|2|3.5|3.5|2.5|3.350|
| **E** |5|3.5|4|3.5|4.5|3.5|**4.075**|

계산: `sum(score[i] × weight[i])`. 순위 E>A>B>C>D. 다른 가중치를 몰래 적용하지 않았다.

| 후보 | 점수의 이유 / 신뢰 / 바뀔 증거 |
|---|---|
| A | 질문 UI와 사건 기반이 가장 많이 맞음. 기존 조사게임과 가까워 정체성3.5. 재사용 신뢰 중간, 재미 낮음. 사람들이 질문의 판별력을 실제 즐기면 E 추월 |
| B | 접근성이 좋지만 장기 감정 결과를 작성해야 해서1인3. 제작비 추정 낮은 신뢰. 반복 인물 둘만으로 강한 agency가 나오면 상승 |
| C | 역할은 다르나 배치 시뮬레이터·균형 작업으로1인2.5. 기술 판단 중간, 재미 낮은 신뢰.2자원 종이 prototype이 이해/재플레이를 보이면 상승 |
| D | 연결망의 재미 잠재4.5는 가장 낙관적 가정. 실제3case 검증조차 비싸서1인2. 재미 신뢰 매우 낮음. edge기각이 핵심 만족으로 관찰돼야 상승 |
| E | 역할·완료·실패를 바꿔 정체성5지만 이것은 **시장 유일성5가 아님**. 추상 UX와 재미 불확실성 반영. 단일case 도메인 비용은 중간 신뢰, 그 외 낮음 |

**민감도:** E의 정체성을5→4로 낮추면3.825로 A가 앞선다. E의 재미를3.5→2.5로 낮춰도 같다. A의 정체성과 재미가 각각0.5 오르면4.175로 E를 넘는다. 현재0.15 차이로 전체 신작을 확정할 수 없다. 따라서 E를 저비용 선행 실험, A를 명시적 비교/대체 후보로 남긴다. 두 방향의 모든 기능을 합치지 않는다.

## 출판사 관점의 최종 반대 심사

1. **왜 존재해야 하나?** 기관의 초안을 수동 승인하지 않고 판단의 근거를 고치는 숙련을 제공할 수 있어서다. 재미 증거는 없다.
2. **왜 PP 대신 고르나?** 속도와 통과 판정보다 ‘무엇을 믿을 수 있는가’를 바꾸고 싶은 사람에게만. 그 수요는 미확인.
3. **세 사건 뒤 왜 계속하나?** 복사·시점·증거 충돌처럼 다른 오류 구조가 나와야 한다. 얼굴만 바뀌면 지속 이유가 없다.
4. **일주일 뒤 기억할 것?** 두 개의 보고가 사실은 같은 출처였고, 자신이 결론을 철회한 순간. 회상 인터뷰로 검증한다.
5. **기술 외 새로움?** 사실을 모으는 대신 기존 결론의 지지를 회수하는 선택. 장르 최초라고 하지 않는다.
6. **PP의 작은 mod로 가능한가?** 화면상 흉내는 가능. 모든 사건의 목표/완료/실패를 이 행동으로 바꾸지 않으면 우리 차이도 성립하지 않는다.
7. **새 창작 위험?** 교정 노동, 추상 그래프, 제도가 스스로 잘 고친다는 낙관 서사. 인계의 한계와 수정 못한 문제도 남긴다.
8. **한 명에게 과한가?** 콘텐츠까지 graph editor/연작/실시간 모델을 넣으면 과하다.1case만 승인한다.
9. **AI가 필요한가?** 현재는 아니다. 분류 마찰이 측정될 때만 한정 도입.
10. **가장 비싸고 실망할 기능?** 자율 NPC와 거대 연결 캠페인. 추천 범위에서 제외했다.
11. **중단의 강한 이유3개?** 실제 반복 재미 증거 없음; 좋은 사건 제작비가 코드보다 클 수 있음; 인접 추리게임과 구매 이유가 충분히 다르지 않을 수 있음.
12. **언제 권고가 틀리나?** 철회가 클릭 정답찾기이고, 새 case 비용이 높고, 다음 사건 선택이 약할 때. 두 번의 제한된 수정 뒤 실패하면 ARCHIVE.

반론으로 수정한 범위: D 혼합 제거, numeric demeanor 제거, 법적 최종처분 제거, AI/음성/공항/장기캠페인 제외, 매 case 복수 정당 결과와 미해결 인계 보장. 이 축소가 매력을 없애면 feature를 다시 늘리는 대신 가설을 폐기한다.

# 04 — Recommended game design: 두 번째 기록

**전부 PROPOSED.** 제품 방향 E 단독이며 A/D의 모든 시스템을 합치는 hybrid가 아니다. 제목은 작업명, 상표 확인 전이다.

## 제품 약속과 대상

한 문장: **이미 내려질 뻔한 판단을 열어, 무엇이 그 판단을 지탱하는지 확인하고 잘못된 근거를 걷어낸다.**

플레이어 fantasy는 전지적 판사/범죄 탐지기가 아닌 기록을 책임 있게 검토하는 사람이다. 짧은 논리·서사 퍼즐을 즐기고, 제한된 정보에서 자신의 이유를 설명하는 플레이어를 가정한다. 게임 설명은 ‘한국판 Papers, Please’나 ‘AI 심사관’에 의존하지 않아야 한다. 이 대상의 규모·지불 의사는 UNKNOWN.

가상의 국경 행정 기록 검토실이라는 맥락을 유지하되, 실제 국가의 재심/난민/체포 권한을 합쳐 만든 기관으로 설명하지 않는다. 실제 제도와 닮은 terminology는 권한 범위 검토 후 사용한다. 이 slice의 결정은 **근거 수정과 담당자 인계 권고**이며 입국 허가/불허 명령이 아니다.

## 세 기둥

1. **근거와 결론을 구별한다.** 두 기록이 같은 원본이면 독립 확인 두 건이 아니다. 자료를 철회해도 과거에 그 자료가 존재했다는 사실은 남는다.
2. **모르는 것을 남길 수 있다.** 모순이 없다는 것, 참으로 확인됐다는 것, 처분에 충분하다는 것은 다르다. 미해결 인계는 정상 엔딩이다.
3. **수정이 사람에게 돌아간다.** 어떤 오해가 바로잡혔고 어떤 절차가 아직 남는지 당사자에게 설명한다. 사람의 표정은 사실 판정 입력이 아니다.

## 핵심 행동과 반응

| 단계 | 플레이어가 아는 것 / 선택 | 상태 변화 / 반응 / 비용 |
|---|---|---|
| 초안 열기 | 누군가 작성한 주장과 근거 링크; 정사 전체는 모름 | observed claim 목록. 읽기 무료 |
| 원출처 따라가기 | 어떤 record가 어디서 왔는지 비교 | 관찰한 source metadata만 노출. 근거 개수와 독립 계보 수 분리 |
| 가설 세우기 | 고의 허위 / 기록 갱신 지연 등 최소2개 | authored hypothesis를 선택하거나 보류; 선택만으로 점수/사실 변화 없음 |
| 철회 미리보기 | 이 근거를 판단에 사용하지 않으면 어떤 주장에 빈틈이 생길지 예측 | 영향 목록을 확인하고 adopt/withdraw. 원자료 불변, undo 가능, 슬롯 소비 없음 |
| 확인 요청 | 어떤 정보가 가설을 구별할지, 아직 무엇이 남는지 | 선택한 조사 결과만 acquire.3 action slot 중1 또는2 소모 |
| 판단 복원 | 얻은 근거로 지지되는 주장만 채택 | derived support 재계산. 참/거짓 자동 도덕 label 없음 |
| 인계 | 수정할 근거·남는 질문·다음 확인 주체 선택 | 명시적 confirm, closure. 조치의 범위와 결과 설명 |

**signature input:** 주장 하나의 근거 채택을 철회하고 결과를 예측한다. **signature output:** 그 자료에만 의존하던 결론들의 지원 상태가 바뀐다. 증거쌍을 눌러 작가가 숨긴 단서를 얻는 시스템과의 차이는 출력이 ‘새 비밀’이 아니라 ‘현재 판단의 한계’라는 데 있다.

아무 근거도 채택하지 않는 것이 최적이어서는 안 된다. 철회만 하고 인계하면 ‘단정은 피했지만 해결하지 못한 범위’가 보고된다. 무근거 유지·무근거 혐의·근거 없는 전면적 무혐의 모두 피한다. 승패를 입국 결과로 계산하지 않는다.

## 첫10분의 목표 흐름

시간은 설계 목표이며 실측 아님. 독해 속도에 불이익을 주지 않는다.

| 예상 구간 | 경험 | 검증 질문 |
|---|---|---|
|0–1분 |‘숙소 허위’ 초안과 자료2개, ‘동의하기 전에 근거를 보라’ | 다음 행동을 스스로 찾는가? |
|1–3분 | 두 보고의 origin ref가 같음을 발견 | 두 문서와 두 독립 근거의 차이를 말하는가? |
|3–4분 | 독립 확인이라는 채택을 철회; 주장 지지가 약해짐 | 사실을 지웠다고 오해하지 않는가? |
|4–7분 | 원장 또는 전송 이력 확인 선택, 변경 시점 검토 | 정보 목표를 가지고 선택하는가? |
|7–9분 | 숙박 관련 단정 수정; 별도 목적 질문은 남음 | 한 오해의 해소를 전체 적격성으로 확대하지 않는가? |
|9–10분 | 인계와 디브리프, 다른 사건에 대한 선택 | 결과를 자신의 결정으로 느끼고 다시 하고 싶은가? |

## 의미 있는 불확실성

- **자료 부족:** 전환 원장에 접근하기 전 숙소 변경은 진술일 뿐이다. 믿음과 입증을 분리한다.
- **시점 차이:**‘17:40에 바뀌었다’와17:57 발급은 관측 대상이 다를 수 있다. 차이는 자동 거짓이 아니다.
- **절차/범위:** 숙소가 확인돼도 다른 목적 관련 질문은 남는다. 지금 충분히 설명할 수 있는 범위로 인계한다.

후속 콘텐츠는 진실한 진술, 실수, 기억의 불확실성, 의도적 거짓을 모두 포함할 수 있다. 거짓은 구체적 증거로만 뒷받침하고 국적·언어·외모·긴장·비협조를 확률 입력으로 쓰지 않는다. 선의의 해명만 반복하면 ‘항상 기관이 틀린다’는 새 정답 암기가 되므로 사건3부터 근거가 유지되는 사례도 필요하다.

## 정보의 종류

| 종류 | 뜻 | 다른 종류로 자동 승격 금지 |
|---|---|---|
| Observation | 플레이어가 읽거나 들은 자료 | 내용을 읽었다고 참이 되지 않음 |
| Statement | 누군가 한 주장 | 어조·자신감은 진실성 인증 아님 |
| Document | 작성/발급된 기록 | 공식 서식이라는 이유만으로 최신/독립 아님 |
| Source lineage | 원본·복사·전송의 계보 | 독립 기관 이름과 독립 정보는 다름 |
| Contradiction | 같은 범위/시점에 양립 불가한 주장 | 단순 시간차·범위차는 미해명 차이 |
| Hypothesis | 관찰을 설명하는 가능성 | 선택한 가설이 정사/점수에 영향을 주지 않음 |
| Supported claim | 현재 관찰·검증·범위에서 지지됨 | 법적 충분성/전역 진실과 다름 |
| Procedural recommendation | 이 권한으로 할 수 있는 인계·수정 | 모델이나 graph가 실세계 처분을 승인하지 않음 |

기존 Statement Lock은 **교체**한다. 발화/문서 선택 UI 아이디어는 참고할 수 있으나 `evaluateStatementLock`와 그 정답 테이블을 기반으로 확장하지 않는다. 새 핵심은 출처·시점·지원 상태이고 ‘critical/smoking gun’ 분류가 아니다.

## 서사·진행·재플레이

슬라이스는 한 기록을 끝낸다. 정식 제품을 검토할 때만3사건 anthology를 만든다: (1)중복 출처, (2)정확하지만 유효기간이 다른 기록, (3)서로 독립인 기록이 실제로 충돌하는 사건. 각 결말에서 정정 전/후 이유와 unresolved 목록을 보여준다. 전 사건의 사람을 ‘범인 네트워크’로 자동 연결하지 않는다.

난도는 문서 수보다 관계의 종류에서 올린다. 초급은 하나의 원본/한 번의 철회, 다음은 대체 근거가 있어 철회해도 유지되는 주장, 그다음은 범위가 다른 두 부분적 진실. 재플레이는 blind random truth가 아니라 다른 확인 경로·다른 범위의 정당한 인계에서 온다. 같은 case를 외운 뒤 새 발견이 남는다고 과장하지 않는다.

결과는 **근거 건전성, 해결한 범위, 남은 불확실성, 절차 이행** 네 줄로 설명한다. 누적 S등급·속도 leaderboard·‘범인 적발’ 점수는 없다. 결과 공개 전 선택 이유와 confidence를 기록하면 나중에 자신의 과신을 확인할 수 있다.

## 비목표와 제품 경계

이번안은 전국 공항 운영, 실제 법률 교육 인증, 경찰/난민 절차 통합, 자율 NPC, 음성 합성,3D 공간,100명 새 인물,클라우드 저장,팀 협업 게임이 아니다. 이러한 기능을 넣지 않아도 핵심 실험이 성립해야 한다.

기존 데이터/초상은 권리와 맥락이 확인된 것만 나중에 재사용한다. 슬라이스에는 인물 실명·실전화·여권번호를 수집하지 않고 가상 record ID만 쓴다. 실제 사람 판단을 돕는 서비스로 연결하지 않는다.

최대 위험은 이 경험이 재밌는 추론이 아니라 ‘잘못된 노드 지우기 숙제’가 되는 것이다. 힌트/정답 강조를 먼저 늘리지 말고, 플레이어가 결과를 예측하고 서로 다른 확인을 고르는지 [07](07_VALIDATION_AND_ROADMAP.md)의 행동 측정으로 판단한다.

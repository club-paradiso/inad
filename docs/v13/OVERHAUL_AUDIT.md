작성 2026-11-11 · 기준 `main` @ `7a63609` · 브랜치 `claude/inad-immigration-game-overhaul-pxtx0k`

근거의 한계: 이 문서의 진단은 저장소 코드, 빌드한 게임을 Playwright로 직접 구동한 기록, 기존 문서(`docs/v12/FIELD_REVIEW.md`, `docs/next-product-audit.md`)에서 나왔다. 사람 플레이테스트는 하지 않았다. 8절의 사용자 유형별 평가는 **가상 페르소나 기반 휴리스틱 평가**이며 실사용자 검증이 아니다. 법무부 내부 기준·전산은 근거로 쓰지 않았다.

## B. 게임 설계 변경

**생성 승객에게 사연을 준다.** 승객마다 여행 주제(관광 10·상용 6·재입국 3), 말투 5종, 본국 직업, 경비 마련 방식을 시드로 뽑는다. 선택 기준은 신고한 입국 근거(관광/상용/재입국)뿐이고 국적·성별·초상은 읽지 않는다. 나이는 직업이 어색하지 않게 하는 데만 쓴다.

**물을 수 있는 것이 늘고, 무엇을 물을지가 선택이 된다.** 일정·숙소·경비·직업 질문이 생겼다. 전부 선택 질문이고 필수 확인(`required`)은 그대로다. 통상 입국자는 여전히 질문 하나로 허가할 수 있고, 더 묻는 만큼 처리시간이 든다.

**이상은 서류에 적힌다.** "의심스러워 보이지만 확인하면 해소되는" 유형을 선언형 데이터(`REVIEW_ANOMALIES`)로 옮기고, 각 유형이 해당 서류의 필드를 실제로 바꾼다. 단서는 그 서류를 열어야 잡힌다.

| 유형 | 서류에 보이는 것 | 해소 |
|---|---|---|
| 숙박 명의 | 숙박예약 `예약자: 동행인 명의` | 국내관계 조회(투숙객 명단) |
| 여행사 발권 | 항공예약 `발권처: 여행사 단체 발권` | PNR 조회 |
| 개인 연락처 | 입국자격 자료 `국내 연락처: 개인 지인` | 국내관계 조회 |
| 항공권 철자(신규) | 항공예약 `탑승객 성명`이 여권과 한 글자 다름 | PNR 조회(여권번호·생년월일 일치) |
| 숙박 기간(신규) | 숙박예약 `첫 N박만 예약` | 국내관계 조회(두 번째 숙소) |
| 체류기간 임박(신규, 재입국 전용) | 외국인등록증 `만료일 임박 · 입국일 현재 유효` | 사증·자격 조회 |

**목적 불일치 불허의 진술을 다양화.** 유상활동 진술 4종(매장·식당·농장·설비 설치)과 그에 맞는 조회 결과. 판정 사유(SIM-A12-PUR)와 필수 확인은 그대로다.

**동행 그룹은 같은 종류의 여행을 한다.** 가족·연인·친구·단체는 관광 입국자끼리, 출장팀은 상용 입국자끼리(2명도 허용) 묶고, 그룹원은 같은 여행 주제를 말한다. 말투·직업·경비는 각자 다르다.

**짧은 근무 순환.** 처음에는 지금까지의 고정 입문 명단(안내 있음). 한 번 마친 뒤에는 새 시드에서 생성 승객 3명(통상·추가확인·통상 또는 불허) + 저작 사건 3건(허가 1건 이상, 비허가 1건 이상, 특수절차 최대 1건)을 뽑아 표준 규칙으로 진행한다. 요약 화면에서 "다른 승객으로 한 번 더" / "같은 승객 다시"를 고른다.

법률·공개절차·각색의 구분:

| 구분 | 내용 |
|---|---|
| 법률(원문 확인) | 취업하려면 취업활동이 가능한 체류자격이 필요하다 — 출입국관리법 제18조제1항(공포 2026-08-04, 시행 2026-10-02, 2026-11-12 국가법령정보센터 조회). 입국심사 요건 — 제12조제3항(v12에서 대조) |
| 게임적 각색 | 생성 승객의 사연·말투·직업, 서류 필드 표기("예약자", "발권처", "숙박기간"), 전산 조회 문구, 추가확인 사건이 재심 인계를 필수로 요구하는 구조 |
| 다루지 않음 | 체재비 최저 기준(금액을 만들지 않음), 재입국허가 면제 요건(문구에서 제외), 국가별 무사증 목록 확대 |

## E. 검증

결과 수치는 PR 본문에 적는다. 테스트가 고정하는 성질:

- 로스터 지문이 `main`과 동일, 사연 질문은 필수에 들어가지 않음.
- 첫 진술에 구 템플릿·결말 암시 표현 없음. 한 근무의 주제 8종 이상·말투 4종 이상.
- 결정적·멱등. 국적·성별·이름을 바꿔도 사연 선택 불변.
- 체류기간·숙소·박수 진술이 최종 서류와 일치(동행 그룹 포함).
- 동행 그룹: 한 종류의 여행, 같은 주제, 같은 입국 여정.
- 이상 유형: 해당 서류에 필드가 있고, INIT 단서 0, 첫 단서는 `DOC_<서류>`, 결과는 CLEAR.
- 통상 관광객의 목적·추가소명 답은 진술 고정 규칙 4(유상활동 문구)에 걸리지 않고, 목적 불일치 불허의 진술은 반드시 걸림.
- 순환 명단: 6명, 저작 3건(중복 없음, 허가·비허가 각 1건 이상, 특수 최대 1건), 동행 기록 없는 승객.

확인하지 못한 것: 사람 플레이테스트, 실제 모델 연동 상태에서의 생성 승객 질문 분류, Firefox·WebKit(로컬은 Chromium만 실행), 운영 배포.

## G. 다음 단계 (우선순위 순)

1. 추가소명 질문을 서류 열람 뒤에만 목록에 나타나게 하기(질문 목록이 이상을 먼저 알려 주는 문제). 한국 모드의 "모든 질문은 처음부터 물을 수 있다"는 설계와 충돌하므로 결정 필요.
2. 1차 창구/재심실 분리(v12 제안 1번). 생성 승객이 사연을 갖게 되어 전제 하나는 충족됐다.
3. 무사증 대상국 목록의 공식 출처 대조 후 생성 분포 수정.
4. 저작 사건 추가(환승 연결편 부재, 출국명령과 강제퇴거의 차이, 조건부 입국허가). 순환 풀 확대.
5. 사람 플레이테스트 5명 이상. 측정: 통상 승객당 질문 수, 서류 열람률, 짧은 근무 재시작률.
6. Figma `[Implemented]` 동기화와 인터뷰 열 밀도 개선안 `[Exploration]`.

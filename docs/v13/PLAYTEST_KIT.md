# INAD v13 — 사람 플레이테스트 진행 자료

대상 빌드: 브랜치 `claude/inad-immigration-game-overhaul-pxtx0k`(PR #53). 이 문서는 진행자용이다. 테스트는 아직 한 번도 하지 않았고, 아래 가설은 전부 미검증이다.

## 1. 무엇을 확인하려는가

| # | 가설 | 틀렸다고 볼 신호 |
|---|---|---|
| H1 | 설명 없이도 첫 심사(승객 1명)를 끝까지 마칠 수 있다 | 5분 안에 첫 질문의 답을 기록하지 못함. 통역 연결을 끝내 못 찾음 |
| H2 | 직접 입력한 질문이 대체로 통한다 | "이렇게 기록할까요?" 확인을 3번 넘게 거절하거나, 입력을 포기하고 목록만 누름 |
| H3 | 첫 심사 뒤 짧은 근무로 넘어간다 | 디브리프에서 "시작 화면으로"를 누르거나 창을 닫음 |
| H4 | 일반 승객이 서로 다른 사람으로 느껴진다 | "다 똑같다", "이름만 다르다"는 말이 나옴 |
| H5 | 서류를 읽어서 이상을 찾는다 | 서류 탭을 열지 않고 질문 목록의 추가소명 문구만 보고 판단함 |
| H6 | 근무 배치만 보고 정규 근무를 시작할 수 있다 | 세부 설정을 열어 헤매거나 배치의 차이를 묻는다 |

## 2. 누구를, 몇 명

- 5명이면 큰 문제는 대부분 나온다. 일반 게이머 2, 시뮬레이션 게임을 즐기는 사람 2, 출입국 업무를 아는 사람 1.
- 출입국 업무를 아는 사람에게는 4절의 추가 질문을 한다.
- 실제 민원인·사건 이야기는 받지 않는다. 테스터의 이름·연락처도 기록지에 적지 않는다(T1–T5로 적는다).

## 3. 준비

- 빌드: `npm ci && npm run build` 후 `node scripts/static-server.js dist 4173` → `http://127.0.0.1:4173/`. 원격 테스트는 PR의 미리보기 배포 주소를 쓴다(배포 상태는 이 문서 작성 시점에 확인하지 않았다).
- 브라우저: 데스크톱 Chrome 1대, 휴대폰 1대(390px 폭). 시크릿 창으로 열어 저장 기록이 없는 상태에서 시작한다.
- 화면 녹화와 소리 내어 생각하기(think-aloud)를 부탁한다. 마이크·음성 인식 기능은 테스트 대상이 아니므로 꺼 둔 채로 둔다.

## 4. 진행 (1인 30분)

진행자는 조작을 알려 주지 않는다. 막혀서 2분이 지나면 "지금 무엇을 하려고 했습니까?"만 묻는다.

| 시간 | 과제 | 볼 것 |
|---|---|---|
| 0–2분 | "이 화면에서 무엇을 할 수 있을 것 같습니까?" | 첫 심사 버튼을 주 행동으로 읽는지 |
| 2–10분 | 첫 심사 1명. "궁금한 것을 직접 입력해서 물어보세요" | H1·H2. 통역 연결까지 걸린 시간, 확인 단계 반응, 답을 못 들었을 때 안내를 읽는지 |
| 10–22분 | 디브리프에서 스스로 다음을 고르게 둔다 → 짧은 근무 | H3·H4·H5. 일반 승객에게 질문을 몇 개 하는지, 서류를 여는지 |
| 22–26분 | 시작 화면으로 돌아와 "정규 근무를 시작한다면?" | H6. 배치를 고르는지, 브리핑에서 무엇을 읽는지(시작만 하고 바로 종료) |
| 26–30분 | 사후 질문 | 아래 |

사후 질문(그대로 읽는다):

1. 방금 한 일을 친구에게 한 문장으로 설명한다면?
2. 가장 답답했던 순간은?
3. 결정을 내릴 때 무엇을 근거로 삼았습니까?
4. 기억나는 승객이 있습니까? 왜입니까?
5. 내일 다시 한다면 무엇을 하겠습니까? 안 한다면 왜입니까?

출입국 업무를 아는 사람에게 추가:

6. 실제 창구와 달라서 거슬린 것은?
7. 1차 창구에서 허가·재심 인계·불허 세 가지만 고르게 한 것은 맞습니까?
8. 과장됐거나 빼야 한다고 본 요소는? (피로도, 지적 횟수, 생체 대조 수치, 현장 이벤트)

## 5. 기록지 (테스터 1명당 1장)

```
테스터 T_ · 유형(일반/시뮬/업무) · 기기(데스크톱/휴대폰)
첫 질문의 답이 기록되기까지: __분 __초
통역 연결: 스스로 찾음 / 안내 문구 보고 찾음 / 못 찾음
직접 입력 __회 중 바로 기록 __ · 확인 후 기록 __ · 포기 __
디브리프 뒤 선택: 짧은 근무 / 같은 승객 다시 / 시작 화면 / 이탈
일반 승객 1명당 질문 수(대략): __   서류 탭을 연 승객: __/6
추가확인 승객의 이상을 어디서 알았나: 서류 / 질문 목록 / 못 알아챔
근무 배치: 바로 고름 / 세부 설정을 엶 / 질문함
막힌 지점(시각·화면·한 말):
인용할 만한 말:
```

게임이 남기는 기록도 같이 본다. 디브리프 하단의 "대화 n회 · 직접 입력 n · 제안 n · 목록 n"과 짧은 근무 요약표를 화면 캡처한다.

## 6. 판정

- H1이 5명 중 2명 이상에서 틀리면 다른 것을 고치기 전에 첫 심사부터 다시 만든다.
- H2가 3명 이상에서 틀리면 직접 입력을 주 경로에서 내리고 제안 질문을 앞세운다.
- H5가 3명 이상에서 틀리면 추가소명 질문을 서류 열람 뒤에만 보이게 바꾼다(지금은 처음부터 목록에 있다).
- 그 밖은 발언과 기록지를 모아 `docs/v13/`에 결과 문서로 남긴다. 결과 없이 "반응이 좋았다"고 적지 않는다.

## 7. 알려진 문제 (테스터가 먼저 말하면 "알고 있다"고만 답한다)

- 직접 입력은 사건에 준비된 질문 범위에서만 통한다. 표현이 다르면 확인 단계를 거친다.
- 추가소명 질문 문구가 이상의 존재를 먼저 알려 준다.
- 이탈리아·호주 등 무사증 대상국 국민이 사증 소지자로 나온다.
- 저작 사건이 12건이라 짧은 근무를 서너 번 하면 같은 사건을 다시 만난다.
- 피로도, 지적 횟수, 생체 대조 소수점 수치는 정리 대상으로 검토 중이다.

# 상태 표시 통합 감사 · 캡처 (2026-11-05)

PR #41(UX Radical Simplification)의 후속 과제. 준비도 % 미터 제거 이후에도 남아 있던 중복 상태 표시를
실측 감사하고, 같은 정보의 중복만 제거했다. **현재 단계는 케이스 바 한 곳**에서만 표시하고,
결정 패널은 결정 가능 상태와 다음 행동만 말한다.

## 감사 결과와 처분

단계 표시 5중 (동시 표시 여부는 뷰포트 기준):

| 표시 | 위치 | 실측 | 처분 |
|---|---|---|---|
| stepper (`#stepper`) | 케이스 바 | ≥1024에서만 표시(태블릿·폰 `display:none`). 단계 진행의 기준 표시 | **유지** |
| 단계 칩 (`#stageBox`) | 케이스 바 | 태블릿·폰에서는 유일한 단계 표시. 데스크톱에서는 stepper와 중복 시 자동 숨김(`data-redundant`), 후속절차 단계에서는 stepper에 없는 정확한 단계명(난민 회부심사·긴급체포 요건 검토 등)을 제공 | **유지** |
| 결정 힌트 (`#actionHint`) | 결정 패널 헤더 | 데스크톱에서 stepper와 동시 표시되며 단계명을 재진술("일반심사 중", "입국재심 진행 중 · …"). 본래 역할은 비활성 버튼의 이유 설명(`aria-describedby`) | **변경** — 단계 재진술 제거. PRIMARY에서는 비움(비활성 버튼 없음), SECONDARY는 "입국재심 인계 완료 · 재심 화면에서 확인한 뒤 결정하십시오", 전용 절차 단계는 "전용 절차 진행 중 · 해당 절차를 마친 뒤 결정하십시오". 종료·난민 문구는 다음 행동 안내라 유지 |
| 근무조 표기 (`#shiftLabel`) | 상단 바 | "제2근무조 · 재심·목적 확인"의 서술자가 단계 계열과 중복. 근무조 번호 자체는 다른 어디에도 없는 정보 | **변경** — `제N근무조`만 표시. 근무조 전환 모달(`views/reports.js`)의 다음 근무조 안내는 별도 맥락이라 유지 |
| 절차 화면 단계 태그 (`.proc-tag.accent`) | 절차 화면 대상자 카드 | 화면 제목·부제가 절차와 법적 근거를 이미 명시하는데 단계명을 다시 표시 | **삭제** |

감찰 표시 2중:

| 표시 | 위치 | 실측 | 처분 |
|---|---|---|---|
| 상태바 감찰 (dots + `0/4`) | 하단 상태바 | 데스크톱·태블릿에서 표시, 폰에서는 상태바 자체가 숨음 | **유지** |
| 케이스 바 감찰 (`strikes-mobile`) | 케이스 바 | 폰에서만 표시되는 카운트 텍스트 | **유지** — 둘은 뷰포트 상호배타이고 `renderStrikes()` 단일 렌더러가 갱신하므로 데이터 중복이 아님 |

단서 표시:

| 표시 | 실측 | 처분 |
|---|---|---|
| 확인 현황 힌트(`#readyHint`)의 "핵심 단서 n/m" | 바로 아래 단서 보드 헤드의 "핵심 n/m · 전체 n/m"와 같은 패널 안에서 중복 | **삭제** — 힌트는 질문·조회 건수만, 단서 건수는 보드 헤드 한 곳만 |
| 단서 카드 렌더링 2벌 | 판단 패널 보드(`renderClueBoard`, 최대 4장)와 절차 화면 패널(`procCluePanel`, 최대 5장)이 같은 카드를 서로 다른 상한으로 렌더 | **통합** — 공용 `clueCardsHTML()`(`system-panel.js`)로 일원화, 상한 4장 통일. 각 표면의 헤드(보드: 핵심·전체 건수 / 절차: 확보 단서·핵심 건수)는 맥락이 달라 유지 |

게이트·잠금은 재도입하지 않았고, 판정 로직(`legal-engine`·`case-engine`)과 `legacy/`는 건드리지 않았다.
접근성: `actionHint`의 `aria-describedby` 연결과 절차 화면 종료 시 포커스 폴백은 그대로이며,
빈 힌트는 비활성 버튼이 없는 PRIMARY에서만 생긴다.

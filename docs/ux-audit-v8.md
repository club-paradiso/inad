# UX 진단 · v8 적응형 작업대 재설계 (2026-09-12)

대상: v7.2 프로덕션(`inad-gray.vercel.app`, main `845d74c`) · 캡처 뷰포트 1440×1000 / 1280×800 / 1024×768 / 768×1024 / 430×932 / 390×844 / 320×568.
판정·저장·데이터 계층은 변경 대상이 아니다(`docs/legal-baseline.md`). 이 문서는 화면 구조·상호작용·시각 언어만 다룬다.

## 2. 문제 분류

### Information Architecture
- **P0 중복 상태**: 심사상태 레일은 DOM을 긁어(`border-console.js` MutationObserver) 판단 근거·요건 검토·전산 결과를 다시 요약한다. 같은 사실이 레일·근거 패널·서류 타일·요건 행에 4번 표시된다.
- **P0 핵심 정보의 순위 역전**: 첫 화면에서 대기열 초상 10명, 운영 KPI 4개, 처리 통계 4개가 현재 승객보다 위에 있다. 승객 이름은 화면의 세 번째 영역(사건 헤더)에서 처음 나타난다.
- **P1 진술 기록 공간 부족**: 좌측 열이 3개 패널로 쪼개져 1440×1000에서도 진술 기록이 약 110px(2줄)만 보인다. 인터뷰가 핵심 루프인데 답변을 읽을 수 없다.
- **P1 근거 패널 과밀**: 요건 검토(6행 카드) + 판단 근거(8노드) + 단서판 + 진행기록 + 사건 메모가 한 스크롤에 있다. 결정 전 "무엇이 확인됐고 무엇이 남았는가"를 한눈에 알 수 없다.
- **P2 서류 상태 타일**: 생체정보·전자입국신고·전산 조회 타일은 우측 근거 노드와 같은 데이터다.

### Interaction Cost
- **P1 전산 조회 6버튼 + 아이콘**: 1024px에서 아이콘만 남고 라벨이 사라진다(`.lookup-tabs button span { display:none }`). 아이콘 6개는 기억해야 하는 어휘가 된다.
- **P1 좁은 화면에서 결정 버튼 도달 불가**: 768·390에서 결정 데스크는 문서 끝(약 3~4화면 아래)에 있다.
- **P2 절차 화면**: 3열 고정 그리드(300/1fr/320)가 1024 미만에서 세로로 쌓이며 실행 버튼이 맨 아래로 밀린다.
- **P2 결정 오입력**: 터치 환경에서 `입국 허가`는 한 번의 탭으로 판정이 확정된다(문서 모달의 확인은 결과 표시일 뿐).

### Cognitive Load
- 동시 노출 패널 8개 + chrome 5행. 서로 다른 강조색 뱃지 12종 이상(코드·상태·단축키·연계·통역).
- 안내 문구가 화면을 설명한다: "질문은 사건기록에 남음", "가상 전산 · 공개/사건 데이터만 사용", "처분 결과보다 선행절차와 근거가 더 중요합니다…", "질문 방식과 대기시간에 따라 대화 반응만 달라집니다." 등 12곳.
- 근거 노드 상태(충족/추가 확인/미충족/미확인) + 레일 상태(OK/CHECK/HOLD/MATCH/READY/ALERT/WAIT/DONE) 두 어휘가 공존한다.

### Visual Hierarchy
- **Card soup**: 패널 > 카드(승객) > 상자(상호작용) > 바. 진술 1건 = 카드, 질문 1개 = 카드, 근거 노드 = 카드 안 필, 단서 = 카드.
- 판단 준비도 %가 헤더·근거 패널 2곳에서 KPI로 강조되지만 힌트일 뿐이다(`readiness()`는 필수 절차 수행 비율).
- 검은 터미널(`.terminal`)은 조회 결과를 "해킹 콘솔"처럼 보이게 하고, 같은 결과가 진술 기록에도 시스템 줄로 기록된다.
- 8~9.5px 텍스트가 결정 버튼 부제·서류 코드·문서 라벨에 쓰여 판독성이 떨어진다.

### Responsiveness
- 1440×1000: 좌측 열 잘림, 우측 근거 패널 스크롤, 결정 데스크만 온전.
- 1024×768: 레일 텍스트 줄바꿈("1차 심사 작업 상 태"), 사건 요약 숨김, 근거 요약 잘림.
- 768×1024 / 390×844: 폴백 안내 배너 + chrome 5행이 첫 화면 전체를 차지. 작업 자체가 불가능(가로 오버플로는 0).

## 4. 새 UX 아키텍처

### 4.1 워크플로와 화면 영역

```
승객 호출 → 신원·입국근거 → 인터뷰 → 서류 확인 → 전산 조회 → 모순·단서 → 법적 판단 → 후속절차
   [사건 헤더]   [대상자]        [인터뷰]    [자료·서류]   [자료·조회]   [판단]        [결정]      [절차 화면]
```

| 영역 | 1차 정보 | 2차 정보 | 1차 행동 | 선택 행동 | 실패·오류 상태 |
|---|---|---|---|---|---|
| 사건 헤더 | 심사번호·성명·국적·단계 | 준비도·처리시간·운영 상황 | — | 운영기록·연계기록 열기 | 이벤트 발생 시 톤 변경 |
| 대상자 | 초상·성명·국적·여권번호·목적·체류·입국편·입국기반 | 태도·언어·동행(판정근거 아님) | — | 동행인 기록 | 언어 미확보 경고 |
| 인터뷰 | 진술 기록(최신이 아래) | 질문 카테고리·잔여 질문 수 | 질문하기 | 언어 선택·통역 호출 | 이해 실패·잠긴 질문 |
| 자료 | 선택 문서 용지·MRZ | 문서 목록·입국 요건 자료 | 문서 선택·확대 | 입국 요건 탭 | 주의 문서(alert) |
| 전산 조회 | 최근 결과(정상·주의·경고·치명) | 조회 종류 6 | 조회 | 재조회 | 동행 없음 등 불가 안내 |
| 판단 | 확인 사항(요건 검토) · 미해결 항목 · 법적 근거 | 단서·진행 기록 | — | 근거 펼치기·출처 등록부 | 준비도 부족 힌트 |
| 결정 | 4개 법정 조치 + 특수절차 | 단축키 | 조치 선택 | — | 비활성(단계별) |
| 절차 화면 | 절차 제목·법적 성격·현재 단계 | 대상자 요약·확보 단서 | 절차 행동 | 질문·조회 | 요건 미충족(체포) |

### 4.2 폼팩터별 레이아웃

| 폭 | 구조 | 이동 |
|---|---|---|
| ≥ 1280 | **3구역 작업대**: 대상자+인터뷰 (320) · 자료+전산조회 (1fr) · 판단+결정 (360). chrome 2행(상단바 48 + 사건 헤더 44) + 상태줄 24 | 없음(동시 표시) |
| 1024–1279 | 3구역 압축(288 · 1fr · 320), 패딩 축소 | 없음 |
| 768–1023 | **2구역**: 작업 영역(인터뷰 ⇄ 자료 세그먼트 전환) · 판단 인스펙터(300, 결정 하단 고정) | 세그먼트 2 |
| < 768 | **과업 이동**: 하단 내비 승객 · 인터뷰 · 자료 · 판단. 헤더는 심사번호·성명·국적·단계·시간만 | 하단 내비 4 |

동일 DOM을 유지하고 `body[data-task]` + `data-zone` 속성으로 표시만 바꾼다. `.desktop-app / .mobile-app` 복제는 금지.

### 4.3 데스크톱 후보 비교

| 후보 | 결정 속도 | 시선 이동 | 동시 비교 | 인지 부하 | 발견성 | 결론 |
|---|---|---|---|---|---|---|
| A. 2열 + 문맥 레일 | 보통 | 적음 | 인터뷰↔서류 비교 시 탭 전환 필요 | 낮음 | 보통 | 인터뷰·서류 동시 비교 불가 → 탈락 |

## 6. UI 카피 정리

삭제: "가상 인물 · 국적은 입국 근거 산정에만 사용"(패널 부제) → 대상자 패널 하단 각주 1줄로 이동, "질문은 사건기록에 남음", "가상 전산 · 공개/사건 데이터만 사용", "출입국관리법 제12조제3항 · 국적은 위험점수가 아님"(부제), "결론 전 필요한 확인을 마치십시오", "처분 결과보다 선행절차와 근거가 더 중요합니다. 재심은 제재처분이 아니라 입국심사의 계속입니다."(결정 하단; 재심 성격은 절차 화면에 이미 있음), "질문 방식과 대기시간에 따라 대화 반응만 달라집니다.", "필요한 확인 절차를 진행하십시오."(초기 힌트 → "필수 절차 0/N").
유지: 판정근거 아님 표기(태도·언어·동행), 법령 조문 인용, 가상 시스템 고지(상태줄), 시작 화면 안내(details).
